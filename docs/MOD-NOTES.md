# PokéSurvivor 繁中版：開發筆記（給之後的自己和 Claude）

> 這份是遊戲主人（ken1130）的要求、已經定案的設計、以及開發時踩過的坑。
> 每次改遊戲前先看這份；有新決定或新坑就補上來。

## 一、主人的固定要求

- 回覆一律用**繁體中文**。
- **技能名稱不要改、不要評論**（這是做給朋友玩的，名字是故意的）。
- 表格缺的數值（CD、機率…）由 Claude 自己補齊、自己平衡，做完再說明補了什麼。
- 主人問「合不合理 / 要不要調」時：**先給分析和建議，等同意再改**。
- **美術要符合原遊戲**：新物件一律用 `js/world/tiles.js` 的像素畫產生器
  （`Pix` / `disc` / `outline`、用生態系的調色盤），不要用簡單的圓形方塊，**不要陽春、不要醜**。
  介面要清楚：看得出是什麼（小地圖要有地形和圖示，不是一堆小點）。
- 會推上 GitHub 的改動，**多人模式也要能用**（房主決定、全隊同步），並說清楚哪些是個人的。
- 不能花錢：Firebase 免費方案、不開任何計費服務（見 CLAUDE.md、記憶）。

## 二、發佈流程（這個 fork 的實際做法）

1. 改 `dev.html` 與 `js/`（`index.html` 是產生的，不要手改）。
2. `node tools/build.js --sin-seo`（**一定要加 `--sin-seo`**，不然 index.html 會塞進原作 pokesurvivor.com 的 SEO）。
3. `node tools/export_data.js`。
4. **不要跑 `python tools/make_seo_pages.py`**：會在改過的標題上當掉，還會改到這個 fork 從不提交的 SEO 頁面。
5. 更新內容寫在 **`js/data/modnews.js`**（`zh` / `en`），不是 `changelog.js`。
6. CSS 改了要把 `dev.html` 裡 `css/style.css?v=…` 的版本號改掉（不然玩家吃到舊快取）。
7. Commit 不加任何 AI 署名；用 **Windows 的 git 推送**：
   `"/mnt/c/Program Files/Git/cmd/git.exe" push origin main`（Linux 的 git 沒有登入）。
8. 不能 `git commit --amend`（會被擋）→ 要補就再開一個新 commit。

## 四、多人同步的原則

- **房主說了算**：怪物生成、撿東西、商店購買、地圖事件都在房主那邊決定，再用事件同步（`coop.js` 的 `emit` / `broadcast`，迷宮事件是 `['dg', …]`）。
- 隊友要求動作（例如購買）→ `G.Coop.request([...])` 送給房主；房主回給特定人用 `G.Coop.sendTo(uid, ev)`。
- **金幣是全隊共用**（存在房主的 `pl.coins`，用 `syncTeam` 同步）。
- 個人物件（光碟、藥水）的 `value` 放擁有者 uid（單人是 `'me'`），畫圖、小地圖、撿取都要檢查擁有者。
- 新增狀態要考慮舊版玩家：未知事件會被忽略即可；新玩家一定會被自動更新。

## 五、踩過的坑

- **不要用瀏覽器原生的 `confirm()`／`alert()`／`prompt()`**（主人覺得很醜）：一律用 `G.Dialog.confirm/alert/prompt`（遊戲風格，async）。

- 西文 key 共用翻譯：例如 `Salir` 已經翻成「登出」，新按鈕不要重用通用字，改用專屬字串（如 `Salir de la tienda`）。
- 新視窗要加進 `tips.js` 的「遊玩中」判斷清單，否則提示框會蓋住按鈕。
- 開局有祝福三選一（state 是 `choice`），測試要先 `G.Boons.pick(0)`，不然遊戲不會跑。

- **換行符號**：大多數 `.js` 是 **CRLF**，`modnews.js` 是 **LF**。用 Python 取代多行字串時要先轉成 `\r\n`，不然對不到；寫錯會混出 `\r\r\n`。
- `sed` 的取代字串裡有 `&` 會被當成「整段比對」→ 要跳脫或改用 Python。
- `js/systems/*.js` 比 `js/ui/ui.js` **先載入**：在模組最外層不能用 `G.UI.$`，改用 `document.getElementById`。
- 畫布的 `fillText` 會自動翻譯，但 **`measureText` 不會** → 量寬度前先 `G.T()`；中文斷行要逐字切。
- 視窗寬度：`.box` 會被內容撐寬，說明很長時卡片會擠到左邊 → 卡片視窗固定寬度並置中（`style.css`）。
- `startRun` 前沒有選夥伴會當掉（測試時要先設 `G.DB.save.partner`）。
- 被動技佔了「目前招式」那格，看起來像要點才有效 → 已改成不能點選。
- 技能寶箱外觀跟原本的「上鎖寶箱」太像 → 改成光碟（新東西要跟既有物件分得開）。
- 組隊時光碟、藥水原本會被隊友撿走 → 改成個人專屬。
- 迷宮戰鬥實測：8 秒混戰誤差太大（進化甚至量到比 LV5 低）→ 改用固定木樁測試；但木樁不會動，地雷／拖尾／衝刺類會被低估。

- 不要把主人的 email 放進公開網頁（除非主人明確要求）。
- 舊的 SEO 靜態頁（`contacto/`、`apoyar/`、`en/support/`、`guia/` 等）是原作者產生的，還帶著原作者 email／捐款／pokesurvivor.com 網域；我們不跑 make_seo_pages.py，要處理得手動改。

- 平行分身（worktree）合併時：同一處「兩邊都新增」的衝突要**兩邊都保留**；不要用「去掉重複行」的方式自動合併（會刪掉像 `return P.canvas();` 這種重複出現的必要行）。合併後的檔案可能變成 LF，比對時注意換行。

- 「暫存外面的怪物」（`EnemyMgr.stash`）的場景（裂縫戰場、商店／神秘房間）**不能疊加**：疊了第二次暫存會蓋掉第一次，回來就卡住。`Rift.start` 在房間內拒絕、`Dungeon.enterRoom` 在房間或裂縫中拒絕。新增類似場景時也要互斥。

- HUD 左上的東西不要寫死 x 座標：金幣藥丸的寬度會變（`G.HUD.coinEnd`），放在它右邊的要跟著它。

- 自動玩家（bot）量難度不可靠：加速跑反應太慢會被包圍；打不死模式又只顧逃跑、等級卡在 4～7 級，跟真人差太多。難度要靠主人和朋友實際遊玩的回饋來調。

  瀏覽器 `~/.cache/ms-playwright/chromium-1248/chrome-linux64/chrome`。
