> 這份是遊戲主人（ken1130）的要求、已經定案的設計、以及開發時踩過的坑。
> 每次改遊戲前先看這份；有新決定或新坑就補上來。

## 一、主人的固定要求

- 回覆一律用**繁體中文**。
- **技能名稱不要改、不要評論**（這是做給朋友玩的，名字是故意的）。
- 表格缺的數值（CD、機率…）由 Claude 自己補齊、自己平衡，做完再說明補了什麼。
- 主人問「合不合理 / 要不要調」時：**先給分析和建議，等同意再改**。
- **美術要符合原遊戲**：新物件一律用 `js/world/tiles.js` 的像素畫產生器
  （`Pix` / `disc` / `outline`、用生態系的調色盤），不要用簡單的圓形方塊，**不要陽春、不要醜**。
  介面要清楚：看得出是什麼（小地圖要有地形和圖示，不是一堆小點）。
- 會推上 GitHub 的改動，**多人模式也要能用**（房主決定、全隊同步），並說清楚哪些是個人的。
- 不能花錢：Firebase 免費方案、不開任何計費服務（見 CLAUDE.md、記憶）。

## 二、發佈流程（這個 fork 的實際做法）

1. 改 `dev.html` 與 `js/`（`index.html` 是產生的，不要手改）。
2. `node tools/build.js --sin-seo`（**一定要加 `--sin-seo`**，不然 index.html 會塞進原作 pokesurvivor.com 的 SEO）。
3. `node tools/export_data.js`。
4. **不要跑 `python tools/make_seo_pages.py`**：會在改過的標題上當掉，還會改到這個 fork 從不提交的 SEO 頁面。
5. 更新內容寫在 **`js/data/modnews.js`**（`zh` / `en`），不是 `changelog.js`。
6. CSS 改了要把 `dev.html` 裡 `css/style.css?v=…` 的版本號改掉（不然玩家吃到舊快取）。
7. Commit 不加任何 AI 署名；用 **Windows 的 git 推送**：
   `"/mnt/c/Program Files/Git/cmd/git.exe" push origin main`（Linux 的 git 沒有登入）。
8. 不能 `git commit --amend`（會被擋）→ 要補就再開一個新 commit。

- **有協作者一起開發（2026-10-15 起，主人＋peter）**：推送前**每次**照下面做，避免互相蓋掉：
  1. `git fetch origin`，用 `git log main..origin/main`、`git diff --stat main...origin/main` 看對方改了什麼，告訴主人。
  2. 先提交自己的改動（指定檔案，不加 .claude/），再拉最新：`git merge --no-edit origin/main`（等於 pull），或 `git rebase origin/main`（只重排自己還沒推的提交；rebase 中有衝突同樣照第 3 點處理，`git rebase --continue`）。不要 force push、不要 reset 掉對方的提交。
  3. 衝突在產生檔（`index.html`、`js/app.min.js`、`version.json`）：不要手動合併，`git checkout --ours` 後用合併後的原始碼重跑 `node tools/build.js --sin-seo` 和 `node tools/export_data.js`。原始碼衝突：兩邊的意圖都保留。
  4. 不要自己覆蓋或還原對方的檔案；對方的改動如果跟主人的決定衝突，先拿給主人決定。
  5. 合併後跑一次無頭測試，沒錯誤才提交合併、推送。
  - 注意：`tools/make_seo_pages.py` 會把原作者的捐款頁（`apoyar/`、`en/support/`）和舊 SEO 頁重新產生出來；我們的流程只用 `--sin-seo`，不跑它。

## 四、多人同步的原則

- **房主說了算**：怪物生成、撿東西、商店購買、地圖事件都在房主那邊決定，再用事件同步（`coop.js` 的 `emit` / `broadcast`，迷宮事件是 `['dg', …]`）。
- 隊友要求動作（例如購買）→ `G.Coop.request([...])` 送給房主；房主回給特定人用 `G.Coop.sendTo(uid, ev)`。
- **金幣是全隊共用**（存在房主的 `pl.coins`，用 `syncTeam` 同步）。
- 個人物件（光碟、藥水）的 `value` 放擁有者 uid（單人是 `'me'`），畫圖、小地圖、撿取都要檢查擁有者。
- 新增狀態要考慮舊版玩家：未知事件會被忽略即可；新玩家一定會被自動更新。

## 五、踩過的坑

- **特效一律像素風（2026-10-16）**：新招式／頭目攻擊的外觀不要再用 `arc`／`ellipse`／`stroke`／`setLineDash` 畫圓、線、漸層（看起來很廉價）。做法：在 `js/entities/vfx.js` 的 `SHAPES` 加小像素圖（用 `o d m l w` 五階調色盤＋`outline()`，要固定顏色就在形狀上加 `cols`），用 `G.VFX.draw`（`pivot` 可指定旋轉點、`step` 角度格數，縮放只用 1／1.5／2 讓每格都是整數像素）；地面範圍用 `G.VFX.oval`（像素列填滿）、外框用 `G.VFX.dashOval`／`dashLine`（會「走動」的點線）；粒子用 `G.FX.sp`（像素圖）和 `G.FX.px`（方塊）。透明度用三段（1／0.66／0.33）。長條重複圖案（荊棘）先拼成一張快取圖再一次畫。已改：酸雨、李家拳、幽冥矛、大自然的洗禮、俠客歐尼爾力場、頭目刀刃／荊棘／火車衝撞、所有 hazards 警示。
