# 已知踩坑紀錄（Known Failures）

改程式前先看一遍，避免同樣的坑再踩一次。每踩到一個新坑就在最下面加一條：
**症狀 → 原因 → 修法 → 以後怎麼避免**。

---

## 1. 區域變數跟外層函式同名 → TDZ 錯誤，效果整個失效（2026-10-15）

- **症狀**：腐蝕酸雨／奈米屌雨沒傷害、沒緩速；李拳的流血也沒作用。遊戲不會跳錯誤視窗，只是效果默默消失（主迴圈 `js/game.js` 會吞掉單一畫格的例外）。
- **原因**：`js/systems/combat.js` 的 `tickDots` 在迴圈裡寫了 `let alive = false;`，但同一個區塊前面又呼叫外層的 `alive(e)` 函式。JS 的 `let` 在宣告前就已經「佔住」名字（暫時性死區 TDZ），所以 `alive(e)` 直接丟出 `ReferenceError: Cannot access 'alive' before initialization`，整段中毒／緩速／流血結算都沒跑。
- **修法**：區域變數改名為 `keep`。
- **以後怎麼避免**：
  - 函式裡新增 `let`／`const` 前，先搜尋同檔案有沒有同名的外層函式或變數（`alive`、`hit`、`dist`、`row`、`stat` 這類常見名字特別注意）。
  - 效果「沒作用」時，第一步先開瀏覽器主控台看有沒有 `[Game] fallo en un fotograma` 錯誤。

## 2. 工作目錄被轉成 CRLF 換行（2026-10-15）

- **症狀**：`git status` 顯示一百多個檔案「有改動」，但 `git diff -w` 幾乎沒有內容。
- **原因**：Windows 端的工具把整個專案轉成 CRLF，repo 裡存的是 LF。
- **以後怎麼避免**：
  - 提交時**只加自己改的檔案**，並用 `git -c core.autocrlf=input add <檔案>` 轉回 LF，不要 `git add -A`，否則會產生一個改動全部檔案的大提交，也會跟 peter 的改動大量衝突。
  - 用腳本改檔案時要注意換行：比對字串要用 `\r\n`，或先判斷檔案是哪一種換行。

## 3. WSL 裡沒有 node（2026-10-15）

- **症狀**：`node tools/build.js` 找不到指令。
- **處理**：下載官方 node 壓縮檔解到暫存目錄再用，不必安裝到系統。無頭瀏覽器測試（playwright 的 chromium）缺 `libnss3`、`libnspr4`、`libasound2` 時，用 `apt-get download` 下載 .deb，`dpkg -x` 解開，再設定 `LD_LIBRARY_PATH` 即可，不需要 sudo。
- **測試存檔**：沒登入時 `G.DB.save` 是空的，測試腳本要先呼叫 `G.DB.playAsGuest()` 才能開局。

## 4. 翻譯句型被較短的句型搶先套用（2026-10-15）

- **症狀**：蛋孵化訊息顯示成「El 蛋 ha eclosionado! ¡皮丘加入了你！」，一半西班牙文。
- **原因**：`js/core/i18n.js` 的 `{x}` 句型是照「加入順序」比對，先找到的就用。`'¡{x} se une a ti!'` 的 `{x}` 能吃下任何字，所以把整句 `'¡El huevo ha eclosionado! ¡{x} se une a ti!'` 也吃掉了。
- **修法**：句型改成依「固定文字長度」由長到短排序，越具體的越優先。
- **以後怎麼避免**：新增含 `{x}` 的翻譯後，可以跑一次全句型檢查（每個西班牙文句型丟進 `G.I18n.f`，確認翻出來的是自己的譯文）。

## 5. 無頭瀏覽器測試：開局會停在選卡（2026-10-15）

- **症狀**：測試腳本 `G.Game.startRun()` 後 `G.Game.state` 一直是 `'choice'`，遊戲不動。
- **原因**：開局會先跳「祝福卡」（`#boon-cards`），升級也會跳選卡，不點的話遊戲是暫停的。
- **以後怎麼避免**：測試腳本用 `setInterval` 自動點掉可見的 `#boon-cards .card`／`#lvl-cards .card`／`#item-cards .card`，等 `state === 'playing'` 再開始測。

## 6. WSL 的 git 推不上去、提交沒有作者（2026-10-15）

- **症狀**：`git push` 出現 `could not read Username for 'https://github.com'`；`git commit` 出現 `Author identity unknown`。
- **原因**：GitHub 登入資訊和 git 作者設定都在 Windows 那邊，WSL 裡的 git 沒有。
- **處理**：推送改用 Windows 的 `git.exe push origin main`（在 WSL 裡也能直接執行）；提交用 `git -c user.name=ken1130 -c user.email=<主人的信箱> commit ...`。
- **換行**：這份專案已設定 `git config core.autocrlf input`，Windows 換行（CRLF）不會再被當成改動。

## 7. 「選擇中…」卡住不能動（迷宮／怪物屋／商店，2026-10-15）

- **症狀**：遊戲停住或角色不能動，頭上一直顯示「選擇中…」，但畫面上沒有任何選擇視窗；按 Esc 沒反應，換房間也一樣。組隊時特別容易發生（怪物屋清完時）。
- **原因**：
  - `G.UI.show(id)` 會把 `SCREENS` 裡**其他所有畫面藏起來**。第二個選擇視窗（升級卡、換道具）一打開，就把第一個藏掉了，第一個的回呼永遠不會被呼叫。
  - 第二個選擇的回呼又因為「不是它讓遊戲暫停的」（`mine === false`）而不讓遊戲繼續。
  - 卡克隆商店的面板在選擇中照樣能點，所以連買兩樣也會觸發。
- **修法**：
  - `game.js`：`offerItem`／`offerBox`／`offerBoon`／`openChoice` 在已有選擇視窗時改成排隊（`offerQ`），沒有視窗時才依序打開。
  - 安全網：`state` 是 choice／levelup 但沒有任何選擇視窗超過 0.5 秒，就自動恢復；組隊時沒打開的升級卡（`coopCards`）會自動補開。
  - `dungeon.js`／`roulette.js`：商店和輪盤不用 `G.UI.show`，選擇中不開商店、按鈕無效；`#scr-shop` 的 z-index 改成 19，選擇視窗永遠在上面。
- **以後怎麼避免**：
  - 新增任何「會暫停等玩家選」的視窗，一律走 `game.js` 的 offer／openChoice（會排隊），並把畫面 id 加進 `CHOICE_SCR`。
  - 遊戲進行中開的面板，不要用 `G.UI.show`（會關掉別的視窗），改用 `classList.remove('hidden')`。

## 8. 組隊後期怪物全部變精英（2026-10-16）

- **症狀**：三人迷宮玩到 9 分鐘左右全滅，怪很多、血很厚，感覺打不完。
- **原因**：`spawner.js` 同時在場的怪物上限（`CAP` 64）是固定的，但組隊時生怪速度會乘上人數倍率。上限很快就滿了，而數量超過上限 85% 後生出來的**全部是精英**（血量 ×1.6、傷害 ×1.25），再疊上人數的血量倍率，就變成無底洞。
- **修法**：上限也依人數放大（`G.Coop.scaleCap`）；所有依人數的倍率集中在 `coop.js`（`scaleRate`／`scaleHp`／`scaleDmg`／`scaleCap`），一個人時全部是 1。
- **以後怎麼避免**：調整「依人數」的數值時，要算「怪物總量（速度 × 血量）」對上人數，也要記得上限和精英門檻會互相影響；一個人時的倍率一定要是 1。

## 9. 商店裡穿過櫃檯／架子（2026-10-16）

- **症狀**：在卡克隆商店裡走路，有時會直接穿過櫃檯、架子或輪盤。
- **原因**：`dungeon.js` 的 `collideFurniture` 只會把人推到「最近的一邊」。移動或衝刺比較快時，一個畫面內就越過家具中線，最近的一邊變成另一頭，看起來就是穿過去。碰撞半徑也只用了身體的一半，角色圖片會陷進家具裡。
- **修法**：記住上一個畫面的位置（`p._fx/_fy`），用「移動路徑有沒有穿過家具框」（`segBox`）判斷；穿過就停在進來的那一面。半徑改成身體的 80%。
- **以後怎麼避免**：自己寫的碰撞只要是「推到最近一邊」，一定要考慮快速移動、衝刺、瞬移時會穿過去，要用上一格的位置判斷方向。

## 10. 數值「只會到某個上限」或「無限疊加」（2026-10-16）

- **症狀**：傳說連戰第 7 隻之後都不會變強；無盡塔的詛咒可以一直疊、後期失控。
- **原因**：`rift.js` 用 `Math.min(1.3, …)` 把連戰血量封頂，傷害也沒有隨勝場增加；`challenges.js` 的詛咒每層隨機抽、沒有次數上限。
- **以後怎麼避免**：做「越來越強」的數值時，同時想清楚：會不會停住（`Math.min` 封頂）？會不會無限乘上去（每層 ×1.25 疊 20 層）？要上限就明確寫在資料裡（例如 `CURSES` 的 `max`）。

## 11. 追蹤彈繞著目標轉圈、永遠打不到（2026-10-16）

- **症狀**：無相神功 Lv5 的愛心「彈射」幾乎不會發生；連續施放時看起來正常（因為下一發會補上）。
- **原因**：愛心用固定速度、有限轉向率追目標。彈射時已經全速往原本方向飛，新目標在旁邊 40 像素，轉不過來就變成繞圈，4 秒後消失。
- **修法**：離目標 70 以內或飛超過 1.2 秒就直接轉向；彈射瞬間把速度直接指向下一個目標。
- **以後怎麼避免**：測「彈射／跳躍」這類機制要用「只放一次」的測試（施放後把 `m.t` 設很大），連續施放會把問題蓋掉。

## 12. 無頭瀏覽器量數值：結果忽高忽低（2026-10-16）

- **症狀**：量神器效果時，同一個測試每次結果不同（燃燒每秒傷害少一半、骰子的 0 只有 2%、暴擊倍率量到 5.7）。
- **原因**：
  - 無頭瀏覽器的畫格不穩，`setTimeout` 的真實秒數跟遊戲時間（`G.Game.st.time`）不一樣。
  - 隨便抓一隻野怪當木樁：每隻屬性不同（屬性相剋倍率不同），玩家也會改打更近的別隻；燃燒的每跳傷害也被算進「命中」。
- **以後怎麼避免**：用 `G.Spawner.spawnAt` 生一隻固定的木樁（血量設很高、`rootT` 定住），其他怪移到很遠；比較「有／沒有」時用**同一隻**；時間用遊戲時間算；要算命中就包住要量的函式（例如 `G.Arts.diceK`），不要數 `hurt` 的次數。

## 13. 組隊「一點小卡」：位置資料被可靠通道卡住（2026-10-16）

- **症狀**：三人組隊（大家都直連、電腦都很好、家裡網路穩），其中一人還是偶爾一頓一頓的。模擬不穩網路時，延遲顯示 1110 毫秒。
- **原因**：`coop.js` 的 `sendFrame` 規定「封包只要有任何事件就整包走可靠通道（ordered）」。戰鬥中幾乎每包都有事件（傷害、怪物出生／死亡），所以位置幾乎都走可靠通道；只要掉一個封包，後面所有位置都要等它重送（排隊阻塞）。
- **修法**：事件另外打包（`{k:'f', x:1, ev}`，不帶 ts）走可靠通道；位置一律走快速通道（不重送、不排隊）。接收端看到 `x:1` 只處理事件。模擬不穩網路時延遲 1110 → 113 毫秒，每 4 秒收到的位置更新 54 → 90 次。
- **以後怎麼避免**：會一直更新的資料（位置、血量）不要放進可靠通道；可靠通道只放「一定要到、晚一點沒關係」的事件。

## 14. 無頭測試：自動點卡片不會關掉技能光碟（2026-10-16）

- **症狀**：跳時間測樓層時卡在 `state === 'choice'`，層主一直不出現（`inGrace` 也不會倒數）。
- **原因**：技能光碟視窗（`#sbox-cards`）裡的卡片只是展示，要按 `#sbox-ok` 才會關；自動點擊先點到卡片就 `return`，永遠按不到確定。遊戲在選擇中時間不走，換層緩衝也不會結束。另外單人升級卡在 `#cards`，不是 `#lvl-cards`。
- **以後怎麼避免**：測試的自動點擊先按 `#sbox-ok`，再點 `#boon-cards`／`#cards`／`#lvl-cards`／`#item-cards` 的卡片；跳時間前確認 `G.Game.state === 'playing'`。

## 15. 組隊雙分頁測試不用 Firebase（2026-10-16）

- 用 `page.addInitScript` 先建立 `window.G`，在 `G.Net` 被設定時（`Object.defineProperty` 的 setter）包住 `on()` 記下處理函式，並把 `send`／`sendFast`／`toHost` 換成 `exposeFunction` 的轉送、`uid` 換成固定值；另一頁收到就呼叫記下的處理函式。兩頁 `G.Game.startRun({seed, host:'H', members:[…]})` 就能測事件同步（範例見 2026-10-16 樓層功能的測試）。
- 注意：遊戲中途改了怪物血量（例如 `spawnBossNow` 之後才改 `maxHp`），隊友收到的 `'ne'` 是舊的血量 → 要在加入前改（`spawnBossNow(pl, t, def, tweak)` 的 `tweak`）。

## 16. 換了精靈圖，遊戲裡還是舊圖，Ctrl+F5 也沒用（2026-10-16）

- **症狀**：重新產生 `assets/pokemon/{dex}/*.png` 後，遊戲裡的角色還是舊的（朝上走還是舊的背面圖）。
- **原因**：動畫表是進戰鬥後才用 `new Image()` 載入，不在頁面載入時抓，所以強制重新整理只會重抓 HTML／JS，圖片照用瀏覽器快取。
- **修法**：自訂角色的 `sprite` meta 加 `v`（產生時間），`sprites.js` 組圖片網址時帶 `?v=`（`G.SPRITE_META` 的一般寶可夢沒有 `v`，網址不變）。
- **以後怎麼避免**：換圖一定要連 meta 的 `v` 一起換（`tools/custom_sprites/` 的產生器會自動寫）；一般寶可夢的圖若要換，也要加同樣的版本號。

## 17. 照片／有背景的圖做原創角色：去背和顏色（2026-10-16）

- **症狀**：主人給的是照片（迪迪）或有榻榻米背景的截圖；`rembg` 預設的 `isnet-general-use` 模型下載到一半逾時；照片縮成 34 像素後灰灰的、沒有外框，跟原作像素寶可夢不搭。白底卡通圖用 rembg 去背反而把細腳吃掉。
- **原因**：模型 179MB 從 GitHub 下載太慢；照片本身對比低，縮圖＋減色後糊成一團；rembg 會把細線當背景。
- **修法**：照片／有背景的圖用 `rembg` 的 **`u2net`** 模型（`new_session('u2net')`，下載得完）；白底卡通圖改用 `make_poses.py --white`（只清跟邊框相連的白色，眼白不會被清掉）。產生器設定加 `outline`（1 像素深色外框）和 `boost`（對比／飽和／亮度）。
- **以後怎麼避免**：新角色先看 `preview.png` 再接進遊戲；去背後的原始圖放 `tools/custom_sprites/src/`（已在 .gitignore，不進 git）。

## 18. 原創角色：原圖臉朝左、SVG、分開的手腳（2026-10-16）

- **症狀**：英雄、湯姆貓往右走時臉朝左（倒著跑）；湯姆貓的 SVG 走路圖 PIL 打不開；倒地圖的手套、腳不見；走路兩格大小不一。
- **原因**：產生器假設原圖臉朝右（右方向用原圖、左方向鏡像）；PIL 不支援 SVG；`load_smooth` 只留最大的一塊；另外用 `sed` 改設定檔時誤把 `"walk2": 26` 改成 16。
- **修法**：設定加 `face_left: true`；SVG 先用 `cairosvg` 轉 PNG；`keep_all` 在平滑模式也有效（只清小於最大塊 1% 的雜點）。
- **以後怎麼避免**：側面的圖先看臉朝哪邊；改 JSON 設定用 python 讀寫，不要用 sed 做模糊替換；看 `preview.png` 每一列大小是否一致。

## 19. 進裂縫／商店／換樓層會卡一下（2026-10-16）

- **症狀**：朋友回報「進傳送門會變很卡」。桌機量到進裂縫那一格 51 毫秒，手機會更久。
- **原因**：`world.js` 的 `setBiome` 每次都 `images = new Map()`，整個畫面的地形區塊要在同一格全部重畫（每塊都是逐像素噪聲運算）；出來時又丟一次再重畫。
- **修法**：每種地形各留一份快取（回到原地形直接用）；`drawGround` 每格最多畫 6 毫秒，其餘先用地板色、下一格再補，而且從畫面中央開始畫。
- **以後怎麼避免**：會「一次清掉快取」的地方都要想到下一格的重畫成本；量卡頓用 requestAnimationFrame 記錄每格時間，看最慢的一格。

## 20. 組隊狀態陣列（myState）的位置撞號（2026-10-16）

- **症狀**：兩個功能平行開發，都把新欄位加在 myState 第 [21] 格（寵物技能次數、成就外觀），合併後互相蓋掉。
- **修法**：外觀改到 [22]；readState 對應 `pk: a[21]`、`cs: a[22]`。
- **以後怎麼避免**：myState 只能往後加，加之前先看 coop.js 現在用到第幾格，並在註解寫清楚 `[n]` 是什麼。

## 21. 自動選取開了關不掉（2026-10-16）

- **症狀**：升級卡「自動選取」切到「全部」後，主人說調不回去。
- **原因**：按鈕只在升級畫面上，而「全部」模式 0.7 秒就自己選完、關掉畫面；從「只選能力卡」要按兩下才回到「關」，第一下切到「全部」又馬上被選走。
- **修法**：暫停選單加同一顆按鈕；升級畫面上一按按鈕就取消這一張的自動選（`autoHeld`）；等待改成 1.2 秒，按鈕上寫「點這裡停止」。
- **以後怎麼避免**：會「自動做事」的開關，一定要放在不會被自動流程關掉的地方，也要能一鍵取消。

## 22. 本地／網站拿到舊的 index.html（2026-10-16）

- **症狀**：伺服器上已經是新版，主人的瀏覽器重新整理後還是舊介面（暫停選單沒有新按鈕）。
- **原因**：`sw.js` 的「先問網路」用一般 `fetch`，會先吃瀏覽器的 HTTP 快取；python http.server 沒有 Cache-Control，瀏覽器會自己猜新鮮時間。
- **修法**：`sw.js` 對程式檔用 `cache: 'no-cache'`（每次向伺服器確認），導覽請求用 URL 重新 fetch；快取名改 `ps-code-v2` 讓舊的 service worker 換掉。
- **以後怎麼避免**：改 sw.js 一定要換快取名；請別人看本地版本時，第一次用 Ctrl+Shift+R。

## 23. 很多招式不會打寶箱（2026-10-16）

- **症狀**：主人回報「技能好像都不會自動打寶箱」（迪迪泡泡拳）。
- **原因**：用 TABLE 數值的招式（fist、spear、hearts、lightning…和原創專屬招）只用 `enemiesIn` 找敵人，沒有敵人就直接結束；而且遠處有敵人被鎖定時，近距離招式會一直等「目標進入範圍」，根本不出手。

- **以後怎麼避免**：新招式寫完要測「附近只有寶箱」的情況；測試時注意遊戲有沒有卡在開場祝福或升級選卡（state 不是 playing 就什麼都不會動）。

## 24. 全面除錯（2026-10-16，5 個分身）學到的

- **組隊事件漏轉**：房主送的新事件（寶藏層 `'ftr'`）在 `coop.js` 的 `applyHostEvent` 沒有 `case`，客人直接丟掉。新增房主事件時，「所有送出的代號」減去「coop.js 的 case」必須是空的。組隊可以用「假資料庫（BroadcastChannel）＋雙分頁」實測，不碰 Firebase。

- **寫死在 HTML／程式裡的樣式**換主題蓋不掉（`#upg-mon` 的 min-width、stages.js 的藍底）：要用 `!important` 或改原始碼。
- **主迴圈的錯誤**只用 console.error 印、連續 180 格會強制結束這局，不會變成 pageerror：自動測試要同時抓主控台錯誤。
- **測試常被視窗卡住**：開場祝福、升級選卡、技能光碟（要按 `#sbox-chest` 再 `#sbox-ok`）、休息站；`state` 不是 playing 時什麼都不會動，量到的數字全是 0。量傷害的雜訊很大（敵人數量、角色升級），只能看大方向。
- worktree 裡含 `$(…)`、`&&` 的長指令會被擋；`pkill -f` 的比對字串不要出現在自己的命令列（會把 shell 也殺掉）。

## 27. 建築／家具畫在「上層」，站在前面的角色被蓋住（2026-10-16）

## 28. 短的通用字被別的畫面佔用翻譯：「進入」變「登入」、「離開」變「登出」（2026-10-16）

## 31. 手機不流暢：ctx.filter、一次預載太多圖、逐點 fillRect（2026-10-16）

- **症狀**：手機後期很卡；有「狂暴」精英時幾乎卡死（CPU 降速模擬下只剩 2 FPS）；每隔一陣子會突然卡一下。
- **原因**：
  - 狂暴敵人每一格都用 `ctx.filter` 染紅，非常耗效能。
  - 預載時，同一格內發出幾十張圖的請求；快取滿了之後，每來一張新圖都要排序一次。
  - 小地圖每 0.5 秒逐點 `fillRect` 2304 次。
  - 後期的瓶頸主要是畫面像素繪製，不是 JS。
- **修法**：
  - 染色圖只做一次就存起來（`G.Sprites.tinted`，跟 `white()` 同樣做法）。
  - 預載改成分批（每 80ms 兩隻）；`evict` 每秒最多一次。
  - 小地圖改用 ImageData 一次寫入。
  - 觸控裝置畫質降到「低」時，內部解析度改成 ×1。
- **以後怎麼避免**：
  - 每格都會跑的繪圖迴圈裡，不要用 `ctx.filter`、`shadowBlur`、`toDataURL`，也不要每格建漸層；需要的話先做好存起來。
  - 量手機效能：用 playwright 的 `isMobile`，加上 CDP `Emulation.setCPUThrottlingRate`（4～6 倍），看 p99 和最慢的一格。
  - 找長畫格要用 Tracing 加 Profiler 對照時間，只看 JS 會漏掉繪製提交。
  - 量測腳本：`scratchpad/pw/mob.js`、`trace.js`。

## 33. iPhone 畫面被壓扁、搖桿對不準（2026-10-17）

- **症狀**：iPhone 14 橫向玩時，整個遊戲畫面被壓扁（圓形的搖桿變成寬是高兩倍的橢圓），搖桿出現的位置也比手指高。有沒有網址列都會發生。
- **原因**：畫布只在 `window` 的 `resize` 事件時重新量尺寸。iPhone 轉向（或網址列收起、展開）時，這個事件常常在尺寸還沒變之前就發出，或乾脆不發。結果畫布的像素大小還停在直向的尺寸（例如 585×1266），被 CSS 拉成橫向的 844×390，比例錯了將近 5 倍。觸控座標用的是螢幕上的真實位置，畫面卻用舊的座標畫，所以搖桿也對不準。
- **修法**：`game.js` 加上 `ResizeObserver` 監看畫布本身、`visualViewport` 的 resize、`orientationchange` 之後延遲再量兩次；每格也比對一次 `clientWidth`／`clientHeight`，不一樣就重設。
- **以後怎麼避免**：畫布尺寸不要只靠 `resize` 事件。測試方式：模擬直向載入，擋掉 resize 事件後再轉成橫向，檢查 `cv.width / cv.height` 是否等於 `clientWidth / clientHeight`（`scratchpad/pw/rotate.js`）。

## 36. 派對模式（大老二）踩到的坑（2026-10-17）

- **`.scr` 預設是置中排版**：全螢幕的牌桌會被擠成畫面中間一小塊。全螢幕畫面要加 `align-items: stretch; justify-content: flex-start; padding: 0 !important`。

- **遊戲開始時把房間設成 `open=false`，斷線的人就回不來**：派對模式要讓房間保持開放，由房主用座位上記的 uid 判斷誰是回來的人。

- **無頭測試**要先設好夥伴（`save.partner`／`owned`），不然 `G.MenuUI.open()` 會出錯；手機模擬一開始的 `#tap-start` 要先點掉。規則測試：`node tools/test/bigtwo_rules.js`。

## 37. 派對模式第二個遊戲（寶可夢屬性牌）踩到的坑（2026-10-17）

- **樣式變數要放在各遊戲自己的牌桌元素上**：症狀是加了屬性牌後，大老二的牌背、頭像大小跑掉。原因是兩個遊戲都在 `#scr-party` 設 `--bw`、`--bh`、`--av`，後載入的會蓋掉前面的。修法：屬性牌的變數只設在 `.tc-table`。以後新遊戲一律把變數放在自己的根元素。
- **有角標的卡牌重疊時，角標會疊到旁邊的牌上**：每張牌要自成一層（`position: relative; z-index: 0`）。

## 30. 投射物招式不經過 `Combat.hit`：新加的命中加成會漏掉（2026-10-19）

- **症狀**：極巨招式只有部分屬性會觸發；組隊時房主一次都沒送出特效。測試裡火花、水槍、電擊、污泥攻擊、泥巴射擊永遠不觸發。
- **原因**：`combat.js` 的投射物命中（`resolve` 裡 `p.hits` 那段）自己呼叫 `e.hurt`，不走 `hit()`；投射物也沒帶招式本身（只有 `payload` 的屬性、燒傷等，環繞型只有 `mid`）。所以掛在 `hit()` 的超級特性、起始招式覺醒、親子愛、極巨招式對投射物全部無效。另外 `MaxMoves.onHit` 原本跳過已倒下的敵人，小怪一擊就死，觸發很少。

- **以後怎麼避免**：要加「每次命中都生效」的效果時，**兩條路都要改**：`hit()` 和投射物命中（搜尋 `p.hits.add`）。測試時要包含投射物、近戰、範圍三種招式，不能只看幾招有觸發就當全部好了。組隊同步的事件用「送出次數＝收到次數」驗證。

## 31. 夥伴選原創角色（圖鑑「其他」）後，重新整理就跳回別隻（2026-10-19）

## 42. 進商店／神秘房間一按方向鍵就被傳出去（2026-10-20）

- **症狀**：剛進房間不小心按到方向鍵，馬上回到地圖；神秘房間也因此用掉、消失。
- **原因**：`dungeon.js beginRoom` 把人放在離門只有 1.6 格（約 77 像素）的地方，而 `roomTick` 的出口判定是「碰到門口 44 像素內就立刻離開」，往下走一下就碰到。
- **修法**：進房位置改成離門 2.4 格；要在門口連續停 `DOOR_HOLD` 0.8 秒（且進房 1.2 秒後）才離開，會提示「停在門口就會離開……」；按「離開」按鈕仍然立刻出去。
- **以後怎麼避免**：任何「碰到就觸發、而且觸發後回不去」的區域（門、傳送、樓梯），都要有停留時間或確認，出生點也要離觸發區遠一點。

## 43. 中毒按「最大血量 %」沒有上限：頭目被依輸出加血後，毒一樣秒掉（2026-10-20）

- **症狀**：練功房測利卡的「長舌鞭」每秒 1.5 萬（進化打 5 隻 7.4 萬），其他招式只有幾百。
- **原因**：`enemy.js` 中毒每 0.6 秒扣 `最大血量 × 1.2% × 層數`（最多 8 層＝每秒 16%）。長舌鞭每下疊 3～4 層、冷卻 0.7～0.9 秒，兩下就滿層；木樁 10 萬血就是每秒 1.6 萬。實戰更糟：頭目的血量會被 `spawner.js dpsFloor` 拉到「20 秒的全隊輸出」（老玩家可到約 70 萬），毒照百分比扣，每秒十幾萬，輸出下限完全沒用。`training.js` 的木樁另外抄了一份同樣的公式。
- **修法**：公式集中到 `Enemy.poisonDmg(e, pl)`（敵人和木樁共用）；`e.boss` 或 `e.dummy` 每層每跳最多 `4 + 1.5×等級`，一般小怪不變。長舌鞭疊毒層數降低。岩漿／毒池／電池（`maxHp × 4%`）對頭目 ×0.25。
- **以後怎麼避免**：跟 #36 一樣，任何「按最大血量百分比、而且會持續或疊加」的效果，都要想到頭目的血量現在會跟著玩家輸出變大；用練功房量測時，若某招數字比別人高一兩個數量級，先查它有沒有百分比傷害。同一段公式不要在子類別（木樁、鯉魚王）各抄一份，改成共用函式。

## 44. 組隊時「別人的招式」在自己畫面上也會閃白、震動、播音效（2026-10-21）

- **症狀**：隊友的英雄大叫，自己的畫面也閃白、鏡頭晃、播頭目音效。
- **原因**：隊友的施放是用 `G.Combat.ghostCast`（`ghost = true`）在本機重播；`fearShout` 的音效和鏡頭震動寫在 `if (ghost) return` 前面，`scareShout` 直接呼叫 `G.Game.flash`。
- **修法**：音效、震動放到 `if (ghost) return` 之後；全螢幕閃光只在 `pl === G.Game.player` 時。
- **以後怎麼避免**：新招式有「全螢幕」等級的效果（flash、camera.kick、大音效）時，一定要想到 ghost 重播；只畫在場上的效果（粒子、圈圈）可以給大家看，會影響整個畫面的只給自己。

## 45. 提示訊息在隊友端出現兩次、或是西班牙文（2026-10-21）

- **症狀**：隊友看到阿爾宙斯的提示兩次；「¡Arceus salvaje apareció!」等組合出來的提示隊友看到西班牙文。
- **原因**：`G.Spawner.say` 在房主端本來就會自動 `G.Coop.say` 廣播，`floors.js` 又自己再廣播一次。另外房主送出去的是「房主語言」的字串（或根本沒翻的拼接字串），隊友端照原樣顯示。
- **修法**：`spawner.say` 統一負責：本機翻譯（已翻過的不再翻，`G.I18n.done`），廣播時附上房主語言與「已翻譯」旗標；隊友端只翻西班牙文原文，房主語言相同就照用。各系統改成把原文（西班牙文）交給 `say`，不要先 `G.T`。
- **以後怎麼避免**：提示一律 `G.Spawner.say('原文')`，不要再自己 `G.Coop.say`；也不要對已經翻譯過的英文再 `G.T`（英文句子裡的字會被當成西班牙文片段亂翻，例如 "Kecleon has" → "Kecleon’s thanks"）。

## 46. 阿爾宙斯的小頭目會極巨化，減益繞過「最多兩個詛咒」（2026-10-21）

- **症狀**：隊友同時中三個詛咒。
- **原因**：33% 召喚的兩隻小頭目走 `spawnBossNow` → `G.GmaxFoe.maybe`，沒排除 `lordMinion`；極巨招式的減益直接寫 `pl.lordSlowT` 等欄位，不經 `applyCurse` 的上限。
- **修法**：`maybe` 排除 `lordMinion`；上限抽成 `G.Floors.canCurse(pl, key)`，`gmaxfoe.js` 也用。
- **以後怎麼避免**：寫同一個玩家狀態欄位的地方不只一處時，把限制抽成共用函式，不要各自判斷。

## 47. 兩頁組隊測試：隊友什麼事件都收不到、`G.Game.state` 一直是 `held`（2026-10-21）

- **症狀**：躲避球的雙頁測試裡，房主正常打完整場，隊友端 `G.Plaza.games` 永遠是空的、狀態 `held`，但沒有任何錯誤。
- **原因**：假的 RTDB（`scratchpad/coop/lib.js`）是用 `BroadcastChannel` 做的，**只在同一個 browser context 內互通**。我用 `page(b, …)` 讓兩頁各開一個 context（`browser.newPage()`），兩頁根本連不上，隊友等不到房主的畫面就進入 `held`（房主「離開」的保護）。既有的 `tlobby.js` 用的是 `b.newContext()` 再 `page(ctx, …)`。
- **修法**：兩頁用同一個 `ctx`。另外 `lib.js` 寫死 8765 埠，自己開別的埠要複製一份改掉。
- **以後怎麼避免**：兩頁測試一律照 `coop/tlobby.js` 的開頭寫（同一 context）；隊友端 `state === 'held'` 又沒錯誤，先懷疑根本沒連上，不要先懷疑遊戲邏輯。

## 48. 派對廣場新場地的告示牌放到房間牆外，`hereOf` 找不到（2026-10-21）

- **症狀**：走到躲避球告示牌座標，上方卡片還是「走到告示牌旁邊……」，`[data-pz="go:dodge:3"]` 不存在。
- **原因**：球場放在 `cy+16` 格、半高 3.8 格，告示牌在球場下緣再 +1.4 格 = `cy+21.2` 格，房間半高 `RH` 只有 20：玩家被牆擋住、到不了告示牌。
- **修法**：`RH` 改 22、球場改 `cy+15`。
- **以後怎麼避免**：在廣場加東西時，先算 `padOf()` 的座標（含告示牌偏移）有沒有在 `±RW/±RH` 之內，再跟其他場地的 `PAD_R`（70 px）圈圈比一下有沒有重疊。

## 49. 躲避球的電腦「閃球」只在原地抖 ±3 px，每球必中（2026-10-21）

- **症狀**：量測時電腦互丟幾乎每球打中或接住，困難等級三回合只花 3～6 秒；受控實驗印出位置是 `0,-3,0,-3,0…`。
- **原因**：閃避方向每幀用「我在球線的哪一側」的符號算；球正對著自己時這個值在 0 附近，每幀翻號，往上走 3 px 又往下走 3 px。修掉之後又出現第二種：閃開 50 px 後球線離自己 >52 px，判定「沒威脅」就走回家，正好走回球的路上被打中。
- **修法**：看到來球時決定一次方向（`c.dsg`：已經偏一邊就往那邊，正面就往球場中央）和目標點（`c.dtx/c.dty`），而且 `c.thr` 一旦為真就維持到球飛過（`dot ≤ 0`）才重置。
- **以後怎麼避免**：AI 的「躲開」「繞開」決策不要每幀依目前位置重算符號；決定一次、存起來、直到那個威脅結束。驗證時印位置序列，不要只看輸贏。
